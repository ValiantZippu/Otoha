# Release Process (Windows)

Target artifact set (#54):

```
release/
├── Otoha-<version>-Setup.exe
├── checksums.txt          (SHA-256, generated at release time — never invented)
└── THIRD-PARTY-NOTICES.txt
```

## Reproducing a release build (#56)

Record these at build time in the release notes:

| Item | Value |
|------|-------|
| Windows | e.g. Windows 11 23H2 (record on build machine) |
| Compiler | MSVC from Visual Studio 2022 17.x (record exact version) |
| Windows SDK | the SDK selected by the VS generator (record exact version) |
| JUCE | 8.0.8 (pinned in CMakeLists.txt via FetchContent GIT_TAG) |
| SQLite | system dev package used at build time (record version) |
| Build command | `OTOHA_RELEASE_VERSION=<ver> sh ./scripts/release.sh` |

The single source of truth for the version is `project(Otoha VERSION …)` in
`CMakeLists.txt` (#34); the installer reads it from `OTOHA_RELEASE_VERSION`,
which `scripts/release.sh` derives from CMake automatically.

## What the release script does

1. Clean CMake configure, Release build (app + every test suite).
2. Runs the full ctest suite — failing tests abort the release.
3. Compiles `packaging/windows/Otoha.iss` with Inno Setup 6 (`ISCC.exe`).
4. Writes SHA-256 checksums into `release/checksums.txt` (#55).

## Installer policies (#27–#31)

* Application files go to `%ProgramFiles%\Otoha` only — never System32.
* User data lives in `%APPDATA%\Otoha` and **survives upgrades** untouched
  (#29/#41/#51): settings, device profiles, custom presets.
* Start Menu shortcut always; desktop icon and "start with Windows" are
  explicit opt-in tasks (#38). The startup registry value is removed on
  uninstall or when the user toggles it off in-app (#32).
* Uninstall removes application files and asks before deleting user data (#30).
* No drivers or virtual audio components ship in this release, so no driver
  privileges/signing apply; if a future virtual-endpoint component is added it
  gets its own installer section and signing story (#31).

## Code signing preparation (#33)

The build supports unsigned development builds and signed release builds:
signing is wired through Inno Setup's `SignTool` directive, configured from
the build machine's environment — never from files in this repository.
Certificates and private keys must never be committed.

## Update architecture (#39–#41)

`Source/App/UpdateChecker.h` defines the seam: a pluggable `UpdateSource`
behind an opt-in "Check for updates" button in About. This build ships
`DisabledUpdateSource` (no network I/O, honest "not configured" answer).
Updates are never forced, never auto-installed, and cannot touch user data.

## Release checklist (#57)

### Build
- [ ] clean MSVC configure & Release build
- [ ] all ctest suites pass
- [ ] no debug-runtime dependencies in the shipped exe

### Audio (requires real hardware — record results, never assume)
- [ ] latency measured, buffer configuration recorded
- [ ] no persistent glitches; device switching works
- [ ] Bluetooth connect/disconnect tested where available
- [ ] sleep/resume recovers without user action

### UX
- [ ] first-launch onboarding completes to audible enhancement
- [ ] Sound UI states match reality (ON/OFF/Unavailable/Recovering)
- [ ] Studio: record → edit → enhance → export still works
- [ ] Advanced panel, diagnostics export, About/licences

### Distribution
- [ ] clean install on a machine without dev tools (#53)
- [ ] upgrade 1.0.x → next preserves profiles/settings (#51)
- [ ] uninstall/reinstall behaves per documented policy (#52)
- [ ] version metadata identical everywhere (#34)
- [ ] THIRD-PARTY-NOTICES.txt ships inside the installer
- [ ] checksums.txt generated by the script, not by hand
